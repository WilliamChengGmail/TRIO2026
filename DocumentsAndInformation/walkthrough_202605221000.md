## 核心變更：ErrorId vs EventCode 路由邏輯

### 新規則

| Level | EventCode 欄位 | ErrorId 欄位 | 用途 |
|-------|:-:|:-:|------|
| **Info** | ✅ 寫入 | ❌ null | 稽核追蹤 |
| **Warning** | ✅ 寫入 | ❌ null | 警示追蹤 |
| **Error** | ✅ 寫入 | ✅ 寫入 | End user → CFS 回報 |
| **Fatal** | ✅ 寫入 | ✅ 寫入 | End user → CFS 回報 |

### 效果

修正後的 DB 記錄範例：

```
-- 之前 (UV Stop)
ErrorId=WRN-3002  EventCode=NULL  Level=Info    ← 三個欄位全部矛盾

-- 之後 (UV Stop)
ErrorId=NULL      EventCode=WRN-3002  Level=Warning  ← 一致且正確

-- Error 等級 (UV Door Interrupted)
ErrorId=ERR-3004  EventCode=ERR-3004  Level=Error    ← 雙寫，CFS 可查
```

## Bug 修正

### UV Stop Level 矛盾 (問題 3)

`LogUvAction` 不再盲目呼叫 `LogInfo`，改為根據 eventCode 前綴自動路由：

```diff
 public static void LogUvAction(...)
 {
-    service?.LogInfo("UV", "UvViewModel", errorId, ...);
+    if (eventCode?.StartsWith("ERR") == true)
+        service?.LogError(...);
+    else if (eventCode?.StartsWith("WRN") == true)
+        service?.LogWarning(...);
+    else
+        service?.LogInfo(...);
 }
```

### UV Door Interrupted 代碼不一致

| 位置 | 修正前 | 修正後 |
|------|--------|--------|
| ErrorCodes.cs | ERR-3004 | ERR-3004 (不變) |
| EventCodeDefinitionSeed.cs | **WRN-3004** | **ERR-3004** |
