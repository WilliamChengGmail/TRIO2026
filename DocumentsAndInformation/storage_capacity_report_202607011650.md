# TRIO2026 儲存容量評估報告

**撰寫者**：Office of William
**分析日期**：2026-07-01
**評估基準**：當前開發環境實際資料庫大小與事件密度
**使用情境**：上班日平均每天 2~3 次操作（以 3 次/天計，取偏大值）

---

## 1. 現況分析 (2026-05-15 ~ 2026-06-26，共 42 天)

| 資料庫 | 當前大小 | 筆數 | 性質 |
|--------|----------|------|------|
| `system_event.db` | **30.9 MB** | 12,900 筆 | 持續成長（事件日誌） |
| `data.db` | 0.09 MB | 38 筆 TestRecord / 231 筆 SampleResult | 持續成長（實驗數據） |
| `system_config.db` | 0.23 MB | ~70 筆設定 | **固定**，幾乎不成長 |
| `main.db` | 0.04 MB | 8 個使用者 | **固定**，幾乎不成長 |

> [!NOTE]
> 當前 42 天的 `system_event.db` 包含大量 **開發階段的除錯事件**（Error 佔 53%），正式上線後事件密度預計**大幅下降**。

## 2. 每次操作的資料量估算

### 2.1 事件日誌 (system_event.db)

| 指標 | 開發階段 (實測) | 正式營運 (預估) |
|------|----------------|----------------|
| 每日平均事件數 | 307 筆/天 | **~80 筆/天** ¹ |
| 每筆平均大小 | 2,514 bytes | ~2,500 bytes |
| 每日增長量 | ~752 KB/天 | **~200 KB/天** |

> ¹ 正式營運時，USB 安全偵測警告（3,027 筆佔 23%）與系統 Error 層級事件（佔 53%）將大幅減少。以開發階段的 Info 層級事件為基準，估算每次操作約產生 25~30 筆 Info/Warning 層級事件。

### 2.2 實驗數據 (data.db)

| 指標 | 實測值 |
|------|--------|
| 每次操作產生 | 1 筆 TestRecord（33 個欄位）+ 平均 6.1 筆 SampleResult（17 個欄位） |
| TestRecord 估計大小 | ~1.5 KB/筆 |
| SampleResult 估計大小 | ~0.8 KB/筆 |
| **每次操作增長** | **~6.4 KB** |

### 2.3 匯出檔案 (USB 上的 Excel/CSV/JSON)

| 檔案類型 | 平均大小 |
|----------|----------|
| Excel 報告 (.xlsx) | ~7 KB/份 |
| report.csv | ~2 KB/份 |
| runinfo.json | ~1 KB/份 |
| **每次操作匯出總計** | **~10 KB** |

> [!TIP]
> Excel/CSV/JSON 匯出至 USB 隨身碟，**不佔用機台本機空間**。僅在「下載到本機」時才會使用本機磁碟。

## 3. 長期容量預測

### 假設條件
- 上班日 = **每年 250 天**（扣除週末與假日）
- 每天操作 = **3 次**
- 每年操作次數 = **750 次/年**

### 3.1 system_event.db（主要空間消耗者）

| 時間跨度 | 事件筆數 (累計) | 預估大小 |
|----------|----------------|----------|
| 1 個月 | ~1,760 筆 | ~4.3 MB |
| 6 個月 | ~10,560 筆 | **~25.8 MB** |
| 1 年 | ~21,120 筆 | **~51.6 MB** |
| 3 年 | ~63,360 筆 | **~154.7 MB** |
| 5 年 | ~105,600 筆 | **~257.8 MB** |

> [!IMPORTANT]
> 系統已內建 **EventLogArchiveService**（按月歸檔 + 30 天自動搬移至備份目錄）。
> 實際運行中的 `system_event.db` 只會保留 **當月** 的事件（約 4~5 MB），歸檔檔案會被搬移至 `Database_Backup/` 目錄。
> 因此 Active DB 不會無限膨脹，但**歸檔備份的總量仍需規劃空間**。

### 3.2 data.db（實驗數據）

| 時間跨度 | TestRecord 筆數 | SampleResult 筆數 | 預估大小 |
|----------|----------------|-------------------|----------|
| 1 年 | 750 | ~4,575 | **~5.2 MB** |
| 3 年 | 2,250 | ~13,725 | **~15.6 MB** |
| 5 年 | 3,750 | ~22,875 | **~26 MB** |

### 3.3 固定空間（不隨時間成長）

| 項目 | 大小 |
|------|------|
| 程式本體 (Self-Contained App) | ~180 MB |
| PrivilegedService | ~80 MB |
| Tools | ~130 MB |
| system_config.db + main.db | ~0.3 MB |
| **固定空間小計** | **~390 MB** |

## 4. 總容量建議

### 5 年使用的空間需求總結

| 項目 | 5 年累計 |
|------|----------|
| 程式 + 固定資料 | 390 MB |
| 事件日誌 (含歸檔備份) | 258 MB |
| 實驗數據 (data.db) | 26 MB |
| OS 暫存/緩衝/SQLite WAL | 50 MB |
| **5 年總計** | **~724 MB** |
| **建議保留 (含 50% 安全餘裕)** | **≈ 1.1 GB** |

### 最終建議

> [!IMPORTANT]
> **建議為 TRIO2026 保留至少 2 GB 的磁碟空間**。
>
> 這個數字已包含：
> - 5 年份的事件日誌歸檔
> - 5 年份的實驗數據
> - 程式本體與所有工具
> - 100% 的安全餘裕空間（應對突發大量錯誤日誌等極端情境）
>
> 以 Win11 IoT LTSC 機台通常配備 **64 GB 以上 SSD** 的標準來看，2 GB 僅佔 3.1%，空間非常充裕。

---

## 5. 額外建議

1. **歸檔策略已就緒**：`EventLogArchiveService` 會自動按月歸檔並搬移舊日誌，Active DB 不會無限膨脹。
2. **極端情境**：若 USB 偵測等功能在某些環境大量觸發 Warning/Error，日誌量可能倍增。建議監控 `system_event.db` 大小，若單月超過 10 MB 需檢視是否有異常事件源。
3. **data.db 不做歸檔**：實驗數據是核心資產，建議永久保留在機台上，5 年僅 26 MB 不構成負擔。
4. **定期備份**：建議每季將 `Database_Backup/` 目錄複製到外部儲存，作為災難復原用途。
